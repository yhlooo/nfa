## Context

当前记忆系统只有一层长期记忆（`~/.nfa/MEMORY.md`），记录用户稳定的偏好和知识，且明确排除时间敏感信息。中期记忆填补这个空白——记录最近几天的关注点、结论和待关注事件。

现有长期记忆的实现是中期记忆的自然参考模板：

```
长期记忆架构                      中期记忆架构（新增）
─────────────                    ──────────────
Memory 结构体                    DailyMemory ← 复用 Memory 的核心模式
  ├─ filePath: MEMORY.md           ├─ dirPath: ~/.nfa/memory/
  ├─ Load/Content/Update           ├─ LoadToday/UpdateToday
  └─ 线程安全 (RWMutex)            ├─ LoadRecent(days) → 合并字符串
                                   └─ 线程安全 (RWMutex)

Summarizer                      DailySummarizer ← 独立的总结器
  ├─ 1min 防抖机制                 ├─ 同样的 1min 防抖
  ├─ SummarizeFlow (LLM 调用)      ├─ DailySummarizeFlow (LLM 调用)
  └─ 激活条件: MEMORY.md 存在       └─ 始终激活（每天新文件）

系统提示词注入                    系统提示词注入
  └─ "## 用户记忆"                 └─ "## 近期动态"（新增区块）
```

## Goals / Non-Goals

**Goals:**
- 按天存储中期记忆到 `~/.nfa/memory/yyyy-mm-dd.md`
- 启动时加载最近 7 天记忆作为 system prompt 快照
- 每轮对话后防抖 1 分钟，触发 LLM 总结当天对话中的时间敏感信息
- 总结内容聚焦于：今日关注、今日结论、待关注事件

**Non-Goals:**
- 不改变现有长期记忆的任何行为
- 不提供中期记忆的手动编辑或查看命令（后续可加）
- 不自动清理 7 天前的文件（保留在磁盘上，只是不加载）
- 不在会话期间动态刷新中期记忆（和长期记忆一致，snapshot 模式）

## Decisions

### 决策 1：独立的 DailySummarizer，不复用现有 Summarizer

**选择**：新建 `DailySummarizer` 结构体，与现有 `Summarizer` 并列运行。

**理由**：
- 两者的 system prompt 内容完全不同（排除时间敏感 vs 聚焦时间敏感）
- 文件管理逻辑不同（单文件全量重写 vs 按天文件定向写入当天文件）
- 激活条件不同（需要文件预存在 vs 始终激活）
- 强行抽象会增加耦合，且现有 `Summarizer` 的接口（`run` 函数签名）绑定于 `SummarizeInput/SummarizeOutput`，改动会波及长期记忆

**替代方案**：抽象通用 `Summarizer` 接口，通过配置区分长期/中期。不采用——两个流程差异足够大，抽象的收益小于成本。

### 决策 2：全量重写当天文件，而非追加

**选择**：LLM 总结时，将「当天已有记忆 + 本轮对话历史」发给 LLM，输出当天文件的完整新内容。

**理由**：
- 与长期记忆的总结模式一致，减少认知负担
- LLM 可在当天范围内去重合并
- 避免追加模式下文件的无限增长
- 跨天不合并——今天不会修改昨天的文件

### 决策 3：Snapshot 模式加载，会话期间不刷新

**选择**：`InitGenkit` 时一次性加载最近 7 天文件内容，构建 system prompt。在整个会话期间（同一个 Initialize/连接）不再重新读取。

**理由**：
- 导致中期记忆更新的当次对话原始内容已在上下文中，无需再引入总结后的版本
- 保持 system prompt 稳定有利于 LLM prompt 缓存命中
- 与长期记忆的行为一致

### 决策 4：中期记忆始终激活

**选择**：每个对话会话都自动启用中期记忆总结，不检查文件是否存在。

**理由**：
- 每天都是新文件，第一次总结时会自动创建
- 无需用户手动引导
- 与长期记忆不同（长期需要 `MEMORY.md` 预存是因为其内容格式有严格模板要求，而中期记忆由 LLM 自主生成）

### 决策 5：文件路径直接使用本地日期

**选择**：使用 `time.Now().Format("2006-01-02") + ".md"` 作为文件名，路径为 `<DataRoot>/memory/`。

**理由**：简单直接，`time.DateOnly` 格式天然可排序。加载最近 7 天时从今天倒推，构造文件路径逐个尝试加载。

## Risks / Trade-offs

- **[风险] 每次启动多一次 LLM 调用（中期总结）**：中期记忆总结和长期记忆总结是两个独立的 flow 调用，会增加模型 API 消耗。→ 两个总结共用同一个 1 分钟防抖窗口，都在对话结束后触发，不会增加调用频率（都是一轮对话一次），只是增加了一个并行的 LLM 请求。

- **[风险] 旧文件堆积**：7 天前的文件不会被自动删除，长期运行会累积大量 `.md` 文件。→ 每个文件只有几 KB，数年积累也不过几十 MB。不需要立即做自动清理，但可在后续版本中按需添加。

- **[权衡] 跨天边界**：如果用户跨午夜使用，总结可能落在不同天的文件。如果对话从 23:55 开始到 00:05 结束，总结可能写入前一天或后一天的文件。→ 总结写入的时间基于「触发总结的时刻」的日期，而非对话开始时间。这是合理行为——写入时间的日期更准确地反映了总结发生的时间。
